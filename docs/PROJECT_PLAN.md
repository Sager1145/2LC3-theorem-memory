# 项目规划与实现判断

## 1. 先决定什么可以进题库

请求中的“全部 theorem”是资料覆盖要求，不是从常识列一组热门逻辑定理。因而从文件读取状态开始建账：当前会话没有直接可枚举附件，转而在 Library 找到对应的课程 ZIP、生成笔记、原始 Markdown、两份旧试题 HTML。对可取原始字节递归展开 ZIP，读取 TEX/Markdown/HTML/PDF 内容，同时保留文件哈希、父归档、行或物理页位置。

不能把文件名中 `9292026` 当成课程年份：该导出归档的课堂课件实际上覆盖 2025 全学期。本版把这些扩展内容与近期笔记/提供练习分开；“当前”只是一种来源分组，不是教师已经讲到哪里的权威判断。

部分 Project 修订文件没有授权的原始字节通道，有的只有索引、且索引读取不完整。有些浏览器保存的 CalcCheck HTML 的代码单元本身为空。因此不能声称已经恢复全部原始 notebook。资料缺口直接显示在应用里，而不藏在 README 尾部。

## 2. 卡片模型与去重

一张卡包括 `id / name / aliases / numbers / displayRef / formula / formulaVariants / kind / topic / domain / sideCondition / current / sources / importantEvidence / frequencyByFamily`。来源有独立 ID，不以人类可见名称作为唯一标识。

同名不等于同卡。不同编号的 De Morgan、Absorption、Weakening、Transitivity 等必须分开。同一个编号下有不同公式的情况，保留明确变体提示；同一公式重复排版、无编号模块别名，只有在同一编号/别名家族且结构匹配时合并，并保留所有原写法。原文无编号、无名称时明确说明，不虚构 LADM 数字或“正式英文名”。

“原文 Important”“同名/编号重复引用”“用户收藏”是三件独立的事。次数按同一来源家族取修订版最大值；完全相同文件、PDF/TeX 两种输出及整套课件拼版不累加。人工补录次数只是经过核对位置的下界。明确的证明提示计数与全篇引用计数分开存储。

## 3. 答题流程

主页自由进入学习节点，或先手动选范围和题型。默认 10 题，每题只承担一项记忆任务。名称输入提供搜索与补全，但不会自动猜中歧义前缀；名称候选总与编号并排。填空题固定符号和括号，把每一处变量变成独立空；键盘也可以无鼠标完成。

提交后显示绿色或纠错反馈，用户主动继续，不设置自动跳走。错误在本轮隔几题返回；若剩余题少则放到末尾，每题最多追加两次。本关结算的首次正确率只统计主问题，避免重试把准确率“刷高”。XP 和连对提供正反馈，但不设置生命值、收费门槛或强制连胜。

错题不是一个简单 ID 集合，而是按题型保留 `wrongModes` 与 `modeWins`。在公式拼写中错过的定理，不能只靠选择名称就清除；同一失败题型须无提示连续正确两次。修复只是归档，不删除历史。用户退出时可以保存未完成队列和已输入答案。

## 4. 为什么不用真值表来直接判所有答案

若只比较整条公式的真值，所有恒真式都会相等，`true` 就能回答 Golden rule、De Morgan、Modus ponens 的任意题。这会把记忆游戏变成无效练习。

本版采用三层：

1. 保留符号和常量的分词匹配；变量之间必须有一致的一一对应关系，不能把两个独立变量都填成 x。
2. 对支持的命题和算术表达式建立语法树，受限使用交换/结合及反向关系标准化；嵌套匹配采用带计算预算的惰性回溯，避免只认某一种局部匹配，也避免无限搜索。
3. 对量词、显式替换、命令、推理规则等复杂表示，回退到保守结构模板，不把解析失败自动视为正确。词法与括号错误给出反馈。

真值穷举仅作为题库的开发期校验，不能替代答案结构检查。自然数截断减法和整数减法的区别、量词的自由变量条件要保留。当前引擎不是通用 SMT 求解器，也不是在线 CalcCheck；正确但超出支持范围的任意变形可能需要按来源结构重写。

## 5. 为什么选原生静态 JavaScript

GitHub Pages 是目标部署面，不需要用户服务器或 AI 账号。HTML/CSS/JavaScript 和本地 JSON 就能实现全部交互。应用不在运行时下载题库、外部字体、框架或模型；没有密钥泄露问题，也不因 CDN 故障失去出题功能。

逻辑引擎与 UI 分文件；前者在 Node 与浏览器共用，自动测试直接执行生产实现。构建只复制白名单目录，排除私人课件、个人备份和测试输出。额外交付内联所有脚本和样式的单文件版，保持同一代码来源，避免两个版本逻辑漂移。

学习状态使用有版本号的本地存储。导入备份限制大小、筛除不认识的卡片 ID，并经过确认才替换。所有可显示的来源字符串和用户回答在插入 HTML 前转义。存储不可用时明确警告并允许导出，不假装已经保存。Service Worker 离线缓存已实现，但在实际站点上的安装与更新还需部署后验收。

## 6. 验收与后续优先级

本次完成：四题型端到端 DOM 操作、名称歧义补全、变量改名、错题按题型修复、备份导入确认、恢复未完成关卡、范围和收藏、重点来源、手机布局、静态构建和部署工作流。

发布前需在自己的 GitHub Pages 地址做一次原生环境验收：刷新后错题和范围仍在、关卡可恢复、备份跨浏览器可导入、HTTPS 离线缓存首次安装及更新行为、iOS Safari 的键盘和字体回退。当前容器不能用已完成的内存存储测试代替这些验收。

资料补全的优先级：先取得 Archive.zip、Week 1/2 修订归档和 A1 原文件；再逐条解决历史课件候选，记录类型与自由变量条件；最后将用户实际的学习进度映射到独立“已学范围”，而非把所有 2025 内容默认打开。新资料不应覆盖已有稳定卡片 ID 或用旧生成笔记反过来证明原稿内容。
